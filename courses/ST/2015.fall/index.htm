Background:

    As the sizes and functionalities of software keep on growing, non-trivial software projects have spent more than half of their budget in testing and debugging.   For Taiwan's high-tech industry, the situtaion is even worse since most software team managers and engineers do not think that they should spend money in software testing.  Such a mentality rooted from Taiwan's industrial strength in OEM and ODM business but is now hurting Taiwan's effort in brand business.   With the know-how in requirement engineering and system testing, Taiwan has no hope in making a successful international brand in the high-tech industry. 

　

Goals:

    The course aims at teaching the students the background theory of software testing and letting them play with advanced testing tools from academia and industry.  In the long-term, we anticipate to produce skillful professionals in software testing business for Taiwan's high-tech industry that can do the following. 

  • Knowing the fundamentals and resources in software testing;

  • Utilizing the research results from academia;

  • Deploying software testing technology to various companies.

    • Project 1 (15%): CUnit, CppUnit, or JUnit, due by Nov. 20, 2015
      • slides by the TA in 2015.
      • It is required that the students use public libraries as SUTs. 
      • Source code coverage analysis are needed in two ways. 
        • You should use the test path generation tool in the textbook webpage to derive test paths and then deduce test input values for each test path.
        • You should then also use public coverage tools to measure the line/branch coverage in test execution. 
      • Use public code coverage tools for Java or other languages.  
    • Project 2 (15%): Image-based testing due by Dec. 18, 2015 with Sikuli (with Firefox on either Linux or Windows)
    • Project 3 (15%): GUI testing with Selenium (with Firefox on either Linux or Windows) due by Jan. 22, 2016
    • Requirement on students' presentations.
      • 1. One student one team.
      • 2. About 10 mins every students with PPT files.
      • 3. One min about the app and its challenge to software testing
    • Project evaluation criteria:
      • 1. Explanation of the SUT.   (10% of total points)
        • It is required that the students use public SUTs instead of writing tiny programs by themselves as the SUTs. 
      • 2. User requirements. (10% of totoal points)
      • 3. Test specification correspondence to user requirements. (10% of total points)
      • 4. Test adequacy. (30% of total points)
        • How many (combinations of) data intervals are tested ?
        • How many permutations of test input events are tested ?
        • Whenever possible, source code coverage analysis with public tools will certainly earn you more credits. 
      • 5. Test evaluation (test oracle) ?　(10% of total points)
        • Purely by human decision ?
        • By test verdicts (or as assertion) encoded in the test scripts ?
        • Or by a test evaluation method ?
      • 6. Test execution demonstration　(10% of total points)
      • 7. Test execution analysis ?　(10% of total points)
        • How many bugs detected ?
        • What kind of bugs detected ?
      • 8. Communication quality ?　(10% of total points)
